# U2-A: selected QBO AP evidence

Main independently accepted the **U2-A read-only local contract**: 36 pure tests, 16 local HTTP controls, eight deadline controls, 215 direct capture/event assertions and five negative controls. The formatting correction additionally passed 76 byte/AST/hash checks and default whitespace validation. Genuine QuickBooks sandbox access, credentials, OAuth, live model calls and final upgrade acceptance remain unexecuted. Worker inference allocation is INR0. `finance_close.qbo.QboAdapter` captures host-selected vendor **Bills** and **BillPayments**. A Bill is a payable; a customer Invoice is outside this connector. No model tool, CLI capture command, ledger import, proposal authority or posting is added. The capture always has `ap_history_complete:false`, `ledger_imported:false`, `posting_supported:false` and `EXTERNAL_HISTORY_NOT_CERTIFIED`, including when selected linked payments agree with the current Bill balance.

## Trusted scope and wire contract

The host supplies an explicit configuration, outside model output: sandbox origin, numeric realm, Bill IDs/expected SyncTokens, BillPayment IDs/expected SyncTokens, vendor crosswalk, local invoice identities, USD and cutoff date. Configuration is copied into immutable tuples and hashed. Unknown configuration fields fail. `origin` is exactly `https://sandbox-quickbooks.api.intuit.com`, API `v3`, `minor_version:75`, configuration schema 1; production and alternate endpoints are rejected.

Only `GET /v3/company/{realm}/bill/{approved-id}?minorversion=75` and the corresponding `/billpayment/{approved-id}?minorversion=75` are built. There are no query strings supplied by the caller, enumeration, pagination, redirects, proxy handling or reads of IDs discovered in `LinkedTxn`, URLs or business text. The sole query parameter is the fixed minor version. At most eight Bills and sixteen BillPayments are selected, with one entity per response and zero query pages. Every selected ID is read twice, so at most 48 GETs fit the default 50-request cap. Missing IDs stop capture; selected IDs cannot establish that all AP records were selected.

Bills require matching identity, expected string SyncToken, vendor, explicit USD CurrencyRef, date, metadata, TotalAmt and Balance. Decimal JSON amounts are converted to integer cents without rounding; negatives, strings, booleans, third decimal places and amounts over 999999999.99 fail. Balance must be within TotalAmt. The actor does not recompute tax or currency conversion. A supplied ExchangeRate must be exactly 1.

BillPayments require Check/CreditCard PayType and one to eight lines. Each line must link exactly one approved Bill for the same vendor. Positive line amounts must sum to TotalAmt. Separate payments can partially settle a Bill; a payment can allocate to multiple Bills through separate unambiguous lines. Duplicate Bill allocations within one payment, multiple links per line, credits, journal entries, customer Invoices, TxnLineId ambiguity, unapproved IDs, payments before a Bill and selected overpayment fail. Selected payment totals are displayed beside Balance as corroborating evidence; disagreement never invents missing history.

`domain:QBO`, explicit `sparse:false`, aware response/metadata timestamps and a full entity response are required by this **conservative subset**. Any status field fails. Optional API fields such as CurrencyRef can be omitted in actual QBO responses; this adapter holds on omission rather than inferring USD. It does not claim that Intuit requires every field required by this subset. Initial and repeated entity hashes must agree, including private fields; wrapper response time may advance. SyncToken or entity drift stops the entire capture. Sequential rereads cannot provide an atomic database snapshot or detect later changes.

## Bounds, redaction and execution gates

Defaults/caps: 24 records, 50 requests, 1 MiB per successful response body, 5 MiB total successful bodies, 15 seconds per request and 180 seconds total. Configuration may lower these bounds. Starts are spaced by at least 0.5 seconds and only one request is in flight. A capture instance is single-use after success or failure. There is no cross-process resume journal or durable no-repeat guarantee. Auth, permission, missing record, 429, 5xx, malformed/schema or uncertain transport results stop capture with **zero automatic HTTP or inference retries**.

The owned transport uses one spawn child per GET, a bounded shared-memory buffer and a monotonic parent deadline covering startup, I/O and retained-handle cleanup. It follows no redirects and uses default verified TLS for the sandbox. Loader execution, when separately authorized later, occurs inside that child; no environment, credential presence, account setup, token refresh or OAuth operation exists here. The trusted runtime loader must be picklable on Windows. Python cannot preempt an OS-blocked process-start call; integration receipts must disclose overruns and uncertain cleanup. Full-tree lifetime RAM is not established by the pure receipt.

`contract-double` accepts an injected function. `local-http-double` requires the owned transport with a literal loopback origin and forbids a token loader. `external-sandbox` requires that same transport class, explicit host `allow_external=True` and a trusted loader; those gates are dormant and do not constitute a grant. No actual external call or loader invocation occurred in this slice. A blocking injected contract function has no process-enforced deadline; late returns are rejected. Owned local HTTP/deadline controls passed under a lease and main review; external compatibility remains pending.

The capture exports selected IDs, trusted local identities, exact cents, currency, dates, SyncToken, response/entity hashes and JSON-path provenance. Events omit raw IDs, paths, names, notes, links, headers, credentials and error bodies. Raw successful response bytes exist transiently for parsing and hashing and are not persisted. A hash plus selected fields is not an archived full ERP response: it cannot reconstruct the source body. Private names, notes, addresses and account detail grant no authority and are absent from exported evidence. Fixed error classes prevent raw exceptions or secret-bearing messages from escaping.
